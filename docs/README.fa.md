# راه‌اندازی حافظه مشترک ایجنت‌ها

نسخه توسعه ۰٫۲ شامل پنل فارسی/انگلیسی و هسته اجرایی است: دیتابیس واقعی، API و MCP، ثبت سشن و تصمیم، ذخیره نقطه ادامه کار و بازیابی آن با هویت اتصال دیگر.

استخراج هوشمند حافظه، embedding، OAuth و اتصال‌های Hermes، OpenCode، Claude Desktop و ChatGPT هنوز پیاده نشده‌اند. برای این مرحله GPU یا کلید API خارجی نیاز نیست. جزئیات نصب و دستورات کامل در [README انگلیسی](../README.md) آمده است.

## نصب با یک دستور

این دستور را در ترمینال سرور اجرا کنید:

```sh
curl -fsSL https://raw.githubusercontent.com/mohammadrezafathi92-web/shared-agent-memory/main/install.sh | bash
```

نصب‌کننده مسیر نصب، زبان، نام مجموعه، ایمیل مدیر، پروژه اولیه، پورت و نوع دسترسی (local، lan یا https) را می‌پرسد. پیش‌نیازهای اوبونتو را در صورت نیاز و با سؤال نصب می‌کند؛ سپس دیتابیس، پنل، حساب مدیر و توکن اولیه را می‌سازد. در پایان آدرس پنل و محل اطلاعات ورود را می‌دهد و برای نمایش توکن سؤال می‌کند.

برای دسترسی با دامنه، `https` را انتخاب کنید؛ دامنه باید از قبل به سرور اشاره کند و پورت‌های ۸۰ و ۴۴۳ در دسترس باشند. HTTPS و تمدید گواهی با Caddy انجام می‌شود. بدون دامنه، `local` و تونل SSH قابل استفاده است. گزینه `ecr` برای دریافت ایمیج‌ها از آینه جایگزین است؛ در این حالت PostgreSQL استاندارد نصب می‌شود.

اگر نصب قطع شد، همان دستور را با همان مسیر دوباره اجرا کنید. رمز و داده‌ها حفظ می‌شوند و حساب تکراری ساخته نمی‌شود. فایل‌های خصوصی در `.install/` هستند. برای مدیریت سرویس‌ها از `.install/manage ps` و `.install/manage logs --tail 100 api` استفاده کنید. این مسیر نصب با نصب دستی قبلی ادغام نمی‌شود؛ برای نصب تازه پوشه خالی انتخاب کنید.

[راهنمای کامل نصب و رفع مشکل](installation.md)

## نصب دستی

در پوشه پروژه، روی دستگاه دارای Docker و Python 3:

```sh
python3 scripts/configure.py
docker compose up --build -d --wait
curl --fail http://127.0.0.1:8765/health
docker compose exec api shared-memory init --workspace team --email owner@example.com --project pilot
```

شناسه workspace و project خروجی را نگه دارید. سپس برای هر محیط، یک token جدا با دستور `shared-memory issue-token` بسازید. فایل `.env` دارای رمز واقعی است و نباید وارد GitHub شود. سرور پیش‌فرض تنها روی همان دستگاه قابل دسترسی است؛ اتصال از شبکه نیازمند تنظیم HTTPS و میزبان مجاز است.

## ورود به پنل

بعد از راه‌اندازی Docker، آدرس `http://127.0.0.1:8765/` را باز کنید. برای پنل یک اتصال جدا بسازید:

```sh
docker compose exec api shared-memory issue-token --workspace-id WORKSPACE_UUID --email owner@example.com --host dashboard
```

توکن خروجی را در صفحه ورود وارد کنید. توکن فقط در حافظه همان زبانه مرورگر نگه داشته می‌شود و با بارگذاری مجدد پاک می‌شود. پنل شامل پروژه‌ها، سشن‌ها و رویدادها، ثبت تصمیم و خلاصه، منبع حافظه، ارتباط سشن‌ها، جست‌وجوی کلیدواژه‌ای و پیش‌نمایش زمینه است. دکمه EN زبان را تغییر می‌دهد؛ چیدمان موبایل و راست‌به‌چپ پشتیبانی می‌شود. ایجاد کاربر و صدور یا لغو توکن فعلاً از CLI انجام می‌شود.

## مسیر ادامه کار بین ایجنت‌ها

۱. با `session_start` سشن بسازید؛ پروژه و `task_key` کار را مشخص کنید.
۲. با `event_append` منبع و با `decision_record` تصمیم را ذخیره کنید.
۳. با `session_checkpoint` خلاصه، کارهای باز و قدم بعدی را ثبت کنید.
۴. در ایجنت دیگر با همان پروژه و کلید کار، سشن جدید بسازید و `context_get` را اجرا کنید.

اطلاعات به‌صورت ادعای ایجنت و همراه منبع نگه داشته می‌شود. تغییر تصمیم به نسخه جدید نیاز دارد و سابقه قبلی حفظ می‌شود. ثبت مجدد همان رویداد در retry، داده تکراری ایجاد نمی‌کند.

## اتصال Claude Code و Codex

فایل نمونه تنظیمات برای هر دو محیط وجود دارد؛ [راهنمای اتصال](adapters.md) روش تنظیم و تولید hookها را توضیح می‌دهد. تنظیمات موجود شما خودکار تغییر داده نمی‌شوند. صف محلی، رویداد را هنگام قطع شبکه نگه می‌دارد و در اجرای بعدی یا flush دوباره می‌فرستد. حالت پیش‌فرض فقط metadata است؛ ضبط همه گفتگوها یا خواندن transcript انجام نمی‌شود. برای تنظیم خودکار همین ادغام، دستور جداگانه‌ی `uv run shared-memory connect-agents --workspace-id WORKSPACE_UUID --email owner@example.com` را اجرا کنید؛ فقط با اجرای صریح شما پیکربندی میزبان را تغییر می‌دهد، `claude`/`codex` را روی `PATH` پیدا می‌کند، برای هرکدام یک توکن صادر می‌کند و فقط وقتی ورودی وجود ندارد یا یکسان است می‌نویسد، هرگز چیزی متفاوت را جای‌گزین نمی‌کند.

جست‌وجوی فعلی کلیدواژه‌ای با یکسان‌سازی نویسه‌های فارسی است. در پاسخ‌ها غیرفعال‌بودن جست‌وجوی معنایی مشخص می‌شود. آزمون پروتکل MCP با دو اتصال مصنوعی، با اجرای یک مکالمه واقعی در خود Claude Code/Codex متفاوت است؛ [گزارش آزمایش](verification.md) این مرز را مشخص می‌کند.

## مرحله بعد

worker، مدل‌های خارجی، نمایه معنایی و توسعه اتصال‌های دیگر. این نسخه برای پایلوت کنترل‌شده و توسعه هسته در نظر گرفته شده است.
